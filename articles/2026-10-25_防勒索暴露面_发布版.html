老系统挂公网三年，可能有三扇门一直开着

2026-10-25 · 防勒索与暴露面

一、先说结论

勒索病毒不是每次都要你点开一个附件。相当一部分事故的入口很朴素：一个对公网开放的业务端口，加一个不够强的密码，被人试开了。

老系统（T3、T+、U8、OA 一类）停产以后补丁就停了，只要那个端口还挂在公网上，这条路就一直敞着。机器不喊疼，所以没人发现。

二、三扇最常见的门

第一扇，业务网页端口。 为了异地同事能登录，T+ 的 8036、OA 的 8888 这类端口被映射到公网。开一天，就有二十四小时在扫的。

第二扇，数据库端口。 SQL Server 的 1433 直接对公网开着——这是最危险的一种，因为它前面没有任何业务登录界面挡着，进来的人拿到的就是数据本身。

第三扇，远程桌面。 3389 对公网开，全靠密码拦。密码一旦在其他地方泄露过一次，这扇门就等于没锁。

三、花半小时自查，不用买任何东西

  1. 把手机 WiFi 关掉，用流量访问 http://你的公网IP:业务端口。能打开页面，说明全网任何人都能打开。
  2. 单独测数据库端口：1433、1434 这类，用在线端口检测工具扫一下，通就是通。
  3. 翻登录日志：大量失败登录、凌晨的登录、一个从没见过的 IP 登录成功——这三样出现任何一样，说明已经有人在门口转了很久。

做完这三步，你大概就知道自己是不是在裸奔。这一步不花钱，也不需要谁配合。

四、关门，还是装门禁

两种思路差得很远。

封 IP 是黑名单思路：今天封了这几个地址，明天对方换一段再来，你得一直盯着日志加规则。追着打，永远追不完。

门禁 是另一种思路：业务端口默认对全网不可见，谁要用，先到门口验一次身份，通过之后端口才临时打开，到点自动关回去。

访问者 ──→ 敲门地址（独立端口）──→ 密码验证通过 ──→ Access Granted ↓ 授权 8 小时 业务端口临时开放（8036 / 11520 / 8888 …） ↓ 正常登录使用

扫描器看不到你的端口，也就无从试密码。它不替代杀毒软件，也不替代防火墙——杀毒软件盯文件，防火墙封已知坏地址，门禁关的是暴露面本身。三者不冲突。

五、十分钟能做完的三件事（按收益排序）

  1. 把数据库端口从公网收回，只留内网或不固定来源的白名单访问。这一条的收益远大于其他任何加固。
  2. 远程桌面：改端口、强密码、失败锁定，条件允许就走 VPN，不要直接对公网。
  3. 业务端口前面加一道门禁。 老版本用户现在有零成本的做法——免费敲门插件就是干这个的，独立端口、密码验证、授权 8 小时，十分钟能部署完。

顺序别反。很多人一上来就研究"装什么杀毒"，其实先把不该出现在公网上的东西收回来，风险就已经降掉一大截。

六、这一周聊了什么

周一到周六，写过的几件小事其实是一件事：先把边界和规矩写清楚，工具才有意义。 选产品先看业务走不走得到财务前面；AI 只接得住"输入明确、动作固定、结果可核验"的活；客户多了钱没多赚，往往是没分层；而安全这件事，边界就是"谁能看见你的端口"。

下周继续。老系统还在跑的，先做一次上面那个半小时的自查，比什么都实在。
