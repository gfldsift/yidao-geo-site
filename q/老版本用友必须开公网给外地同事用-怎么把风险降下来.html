老版本用友必须开公网给外地同事用，怎么把风险降下来？

先接受一个前提：只要端口对公网开着，它每天都被扫。 剩下能做的，是让"扫到"不等于"能进"。

先接受一个前提：只要端口对公网开着，它每天都被扫。 剩下能做的，是让"扫到"不等于"能进"。

按收益排序，三件事：

一，别让数据库端口露在外面。 SQL Server 的 1433 是最危险的一类，因为它前面没有业务登录界面挡着，能连上就等于摸到数据。这一条收益最大，也最容易被忽略——很多人只盯着业务网页端口，忘了数据库。

二，业务端口加一道门禁。 思路是：业务端口默认对全网不可见，访问者先到另一个独立端口验证一次密码，通过之后业务端口才临时开放，授权到期自动收回（常见做法是 8 小时）。扫描器看不到端口，也就无从试密码。老版本用友（T3/T+/U8 一类）不需要换系统就能加，部署十分钟级别。这类工具市面上已有零成本的做法，可以先拿一台非核心服务器试。

三，远程桌面单独处理。 3389 不要直接对公网；改端口、强密码、失败锁定三件一起做，条件允许就走 VPN。

顺便说一个常见误区：只封 IP 不管用。封掉的是已知地址，对方换一段再来，你得一直盯日志加规则。黑名单是追着打，门禁是关掉暴露面本身，两者成本差很远。

最后提醒一句：门禁不替代杀毒软件，也不替代备份。它管的是"谁能看见端口"，进来之后的事还得靠另外两道。
