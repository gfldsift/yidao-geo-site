用友 T3/T+ 停产好几年了一直没升级，现在担心勒索病毒，第一步该做什么？

先说结论：第一步不是升级，也不是装杀毒软件，是先把自己的暴露面收回来。 升级要预算、要停机、要评估，快则一两个月；而端口暴露是当天就能改的事，风险的大头恰恰在这一块。

先说结论：第一步不是升级，也不是装杀毒软件，是先把自己的暴露面收回来。 升级要预算、要停机、要评估，快则一两个月；而端口暴露是当天就能改的事，风险的大头恰恰在这一块。

具体三个动作，按收益排序：

一，把数据库端口从公网收回。 SQL Server 的 1433 这类端口，只要对公网开着，前面就没有任何登录界面挡着，扫到就是直连。改成只允许内网访问，或者只放固定的出口 IP，这一个动作能挡掉很大一部分自动化攻击。

二，远程桌面不要裸着对公网。 3389 改端口只是降低噪音，不等于安全。密码要强、要开失败锁定，能走 VPN 就走 VPN。很多事故不是被"攻破"的，是密码在别处泄露后被"试开"的。

三，业务网页端口（比如 T+ 的 8036、OA 的 8888）在公网上给一道门禁。 现在的做法有两种：一种是白名单，只允许固定的办公 IP；一种是门禁式——端口默认对外不可见，用的人在独立端口验一次密码，业务端口才临时开放几小时，到点自动关回去。后者更适合有异地办公、IP 不固定的场景，而且老版本用户有零成本的做法。

做完这三步，再谈升级。这里有个常见误区：补丁停了挡的是漏洞利用，挡不住别人试你的密码，这是两件事。

该泼的冷水：以上只能把门关上，挡不住已经进来的东西。如果服务器上有过陌生账号、异常计划任务、杀软被关掉，那可能已经中招，得先取证处置再谈加固——顺序反了会把证据洗掉。
